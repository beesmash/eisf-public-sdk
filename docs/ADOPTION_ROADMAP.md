# EISf Public Adoption Roadmap

The public goal is to make EISf easy to inspect, implement, test, cite, and teach without exposing proprietary Beesmash/JANUS internals.

## Near term

1. Improve onboarding with executable hello-world examples.
2. Publish package-registry releases after registry ownership and signing policy are established.
3. Create a small documentation site generated from the public repository.
4. Collect third-party conformance reports and implementation feedback.
5. Archive stable public releases with a long-term scholarly/software archive when appropriate.

## Compatibility ecosystem

A third-party tool should be able to:

- read the public specification;
- produce a portable five-stage case;
- validate that case;
- run the public conformance driver;
- publish a reproducible self-test result.

## Education

Potential public learning material includes:

- EISf in software engineering;
- EISf for incident analysis;
- EISf for research planning;
- EISf for policy-neutral decision support;
- EISf for local/offline AI.

## Boundaries

Adoption work must not require publication of private JANUS prompts, KRONOS orchestration, private scoring, private model routing, client data, or trade-secret implementation methods.
